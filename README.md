# keiba-streaming

宝土蓮華の競馬配信用コントロール画面と透明オーバーレイ。購入済み馬券の記録・表示・的中判定に使えます。馬券を購入する機能はありません。

**はじめて使う方は、GitHub Pages版をOBSに登録してください。** アプリのダウンロード、Node.jsのインストール、コマンド入力、GitHubアカウントは不要です。ローカル版は、Node.jsやターミナルの操作に慣れている方向けに後半で説明します。

- [ブラウザで操作画面を試す](https://rengehoudo.github.io/keiba-streaming/)
- [GitHub Pages版をOBSで使う](#obs-pages)
- [ローカル版を使う（開発環境の知識がある方向け）](#local-version)
- [リポジトリ](https://github.com/RengeHoudo/keiba-streaming)

## はじめに：GitHub Pages版をOBSで使う

用意するものは、OBS Studioとインターネット接続です。操作画面を「カスタムブラウザドック」、配信に映す画面を「ブラウザ」ソースとして、両方とも同じOBSに登録します。

**配信中の入力はOBS内のドックで行ってください。** Chrome・Edgeなどで開いた操作画面の記録は、OBSへ自動共有されません。

### 1. OBSに操作画面を追加する

1. OBSの「ドック」→「カスタムブラウザドック」を開きます。
2. ドック名に `競馬コントロール`、URLに次のアドレスを入力し、「適用」を押します。
3. 開いた操作画面を使いやすい位置に配置します。幅350〜450pxが目安です。このドック自体は配信には映りません。

操作画面のURL：

```text
https://rengehoudo.github.io/keiba-streaming/
```

### 2. OBSに配信画面を追加する

1. 配信に使うシーンの「ソース」で「＋」→「ブラウザ」を選びます。
2. 名前を `競馬オーバーレイ` などにして、次のURLと設定を入力します。
3. 背景・コメント・VTuberモデルを別のソースで配置します。背景のソースはオーバーレイより下に置いてください。

配信画面のURL：

```text
https://rengehoudo.github.io/keiba-streaming/overlay.html
```

| ブラウザソースの設定 | 入力する値 |
| --- | --- |
| ローカルファイル | OFF |
| 幅 | `1920` |
| 高さ | `1080` |
| カスタムCSS | 初期設定のまま |
| 表示されていないときにソースをシャットダウン | OFF |
| シーンがアクティブになったときにブラウザの表示を更新 | OFF |

設定項目の説明は[OBS公式のブラウザソースガイド](https://obsproject.com/kb/browser-source)でも確認できます。

### 3. 表示を確認して使い始める

1. OBS内の操作ドックで「＋」からレースを追加し、「レース情報・予想印」でレース名などを入力します。「JRAからレース情報を取得」で予定レースを選ぶこともできます。
2. 「馬券を登録」または「買い目を貼り付け」で購入済みの馬券を入力します。初回のお試しには「架空のサンプルで試す」も使えます。サンプルは既存の記録を置き換えるので、確認画面を読んでから実行してください。
3. OBSのプレビューにレース名と馬券が表示されることを確認します。ドックでレース状態を変更し、配信画面にも反映されることを確認してください。
4. 配信中は操作ドックを開いたままにします。レース後は着順の入力やJRA結果の取得で、的中判定・払戻・収支を更新できます。

このアプリのOBS内での保存領域共有・同期は実機未検証です。配信前に上の手順で確認してください。確認済みの範囲は[検証記録](TESTING.md)に記載しています。

### 記録の保存・引き継ぎ

記録は操作に使ったブラウザ内に保存されます。OBS内で入力した場合はOBSのブラウザ保存領域に残り、GitHubや外部サービスへ購入記録を送信しません。別PC・別ブラウザとは自動共有されません。

- 操作ドックの「バックアップ・OBS設定」→「JSON保存」で、記録をファイルに保存できます。OBSのブラウザデータを消す前や、PCを移行する前に保存してください。
- Chrome・Edgeなどで作った記録をOBSへ移す場合は、元の操作画面で「JSON保存」し、OBSの操作ドックで「JSONバックアップから復元」→「内容を確認して復元」を使います。
- **復元すると現在の全レースを置き換えます。** 残したい記録は先にJSON保存してください。CSVは集計用で、復元にはJSONを使います。

### 表示が更新されないとき

- 入力しているのがOBS内の操作ドックか確認してください。外部ブラウザでの変更はOBSには反映されません。
- ドックとブラウザソースのURLが、上に記載した同じ `https://rengehoudo.github.io/keiba-streaming/` 配下になっているか確認してください。
- 操作ドックとブラウザソースを再読み込みし、レース状態を変更してもう一度確認してください。
- 同期できない環境では、後半の[ローカル版](#local-version)も利用できます。

## 操作

- 「＋」でレースを追加。「レース情報・予想印」から開催日、場所、R、名称、発走予定時刻などを入力します。
- 「JRAからレース情報を取得」はブラウザ版・ローカル版の両方で使えます。開催日を指定して番組表から選択してください。予定情報なので、当日の変更と出走頭数は手動で確認してください。取得失敗時は既存記録を変更しません。
- 「馬券を登録」で馬番を選ぶか、「買い目を貼り付け」で複数点を解析します。プレビュー確認後に登録します。同じ券種・買い目も別の購入記録として登録し、購入額・払戻額にすべて反映します。貼付内の重複や再貼付も追加します。
- 単勝・複勝・馬連・ワイド・馬単・3連複・3連単・WIN5に対応。馬単・3連単は選択順が着順です。購入額は100円単位です。
- 馬番は①〜⑱の丸数字。「まとめて表示」はワイド `② − ⑤ ⑥ ⑧`、3連複 `① − ⑥ − ⑦ ⑧`、馬単 `② → ⑤ ⑥ ⑧` のように共通する馬番と相手を表示します。全買い目を展開して一致を確認し、異なる金額を混ぜません。
- 1ページ最大8行、初期設定は10秒の自動切替です。全券種を巡回するので手動で券種を切り替える必要はありません。間隔変更・停止・前後移動、従来の一覧／フォーメーション表示にも対応します。
- 「着順を入力して的中判定」で1〜3着の馬番を入力すると、配当なしでも当たり・外れを確認できます。着順だけの保存では払戻は確定しません。
- 「着順・的中判定・払戻」の「JRAの結果・WIN5情報を取得」で、JRA公式から上位3着・出走頭数・全7券種の確定払戻金を取得します。購入額 ÷ 100 × 的中した組み合わせの確定払戻金で計算し、払戻と収支を保存します。再取得しても加算を重複しません。
- 自動確認は初期状態でONです。購入記録があるレースを発走予定時刻（日本時間）後から約60秒ごとに確認します。別レースを選択しても継続し、未公開・取得エラー・保存競合後も再試行します。確定払戻の保存後にそのレースの確認を終了します。レースごとにOFFにでき、再読み込み後も設定を保持します。多数の対象がある場合は順番に取得するため間隔が延びます。
- 発走時刻未入力の通常レースは、時刻を設定するか「レース中」「確定待ち」へ切り替えてください。過去日の未確定購入も確認対象です。別タブ表示中も動作しますが、ブラウザの省電力・タブ休止・端末スリープで遅れることがあります。操作画面を閉じた後は動作しません。
- WIN5は「WIN5の記録を追加」で専用記録を作成し、開催日を設定します。第1〜第5レースの順に馬番を選ぶか、`WIN5 01-01-03-04-05 100円` の形式で貼り付けます。異なるレースで同じ馬番を指定できます。JRA取得で対象5レース・的中馬番・100円あたりの確定払戻金を保存し、通常馬券と同様に日別収支・表示・CSV・JSONに反映します。
- WIN5の自動確定では対象5レースの通常結果も照合します。同着・取消・返還・的中票なしなどを自動確定できない場合は、公式結果を確認して理由付きの手動払戻を保存してください。5レースの勝馬と配当（例：`WIN5 01-01-03-04-05 12,340円`）の手動入力にも対応します。
- 自動取得はJRAの直近結果一覧にある通常レースに対応します。同着・取消・除外・競走中止・特別払戻等は自動確定せず、公式結果を確認した上で手動払戻を使います。取得時は既存の手動払戻を自動計算に置き換え、修正履歴を残します。出典と取得時刻を画面で確認できます。
- 払戻には必要な100円あたり配当と確認・確定チェックが必要です。未入力は0円確定にしません。同着・取消・返還などの例外は理由付きの手動払戻総額で扱います。
- レース状態は「発走前 / レース中 / 確定待ち / 確定」の4段階で切り替えられます。「確定」は表示の切替であり、払戻の確定とは別です。購入内容の修正後は払戻の再確認が必要です。
- 的中演出は約4秒・無音。収支の表示と独立して実行・停止できます。

貼付例（架空）：

```text
ワイド ボックス 3組
03-07 100円
03-14 200
07-14
3連単
14→03→07 100円
```

金額がない行には入力した既定額を適用します。ながし・BOX・フォーメーション等の見出しから買い目を追加展開しません。見出しの下に実際の組み合わせを記載してください。不明行と、同じ買い目も追加されることをプレビューに表示します。

## ローカル版（開発環境の知識がある方向け）

Node.jsのインストールやターミナル操作に慣れている方向けです。PCでサーバーを起動し、配信中も動かしておく必要があります。記録をPCのファイルとして管理したい場合や、外部ブラウザの操作画面とOBSを同期したい場合に利用できます。

### GitHub Pages版との違い

| 機能 | GitHub Pages版 | ローカル版（Node.js） |
| --- | --- | --- |
| 起動方法 | OBSに公開URLを登録 | Node.jsでサーバーを起動 |
| 馬券登録・貼付・編集・的中判定・収支 | 対応 | 対応 |
| 丸数字・まとめ表示・自動ページ切替 | 対応 | 対応 |
| 記録の保存先 | 操作に使ったブラウザの保存領域（IndexedDB） | PCの `data/` |
| 操作画面と配信画面の同期 | 同じ保存領域を使う画面同士。OBSではドックとソースを同じOBS内に登録し、事前確認 | OBS・外部ブラウザから同じローカルサーバーへ接続 |
| JRAの予定レース情報取得 | 公開API経由で公式開催日程から取得 | 公式開催日程から取得 |
| JSONバックアップ・復元、CSV出力 | 対応 | 対応 |

JSONは両方の版で共通です。ローカル版のバックアップをGitHub Pages版へ復元することも、その逆もできます。復元時は現在の全レースを置き換えるので画面で確認してください。

### ローカル版の起動

Node.js 22以降が必要です。通常の起動には外部パッケージやAPIキーは不要です。

1. [ローカル版をZIPでダウンロード](https://github.com/RengeHoudo/keiba-streaming/archive/refs/heads/main.zip)して展開するか、このリポジトリをcloneします。
2. Windowsでは `start.bat` を実行します。ターミナルからは `npm start` でも起動できます。
3. 操作画面 `http://127.0.0.1:8765/control` を開きます。
4. 起動したウィンドウは開いたままにします。終了は `Ctrl+C`。

PowerShellで `npm.ps1` が拒否される場合は `npm.cmd start` または `node src/server.js` を使用してください。既存版の更新後はサーバーを再起動し、操作画面とOBSブラウザソースを再読み込みします。

### ローカル版をOBSに登録する

1. 「ドック」→「カスタムブラウザドック」に `http://127.0.0.1:8765/control` を登録します。幅350〜450pxを目安に配置します。
2. シーンに「ブラウザ」ソースを追加し、`http://127.0.0.1:8765/overlay`、幅1920・高さ1080に設定します。
3. 背景・コメント・VTuberモデルは別のOBSソースで配置します。

ローカル版では、同じPCのChrome・Edgeなどで開いた操作画面からもOBSへ反映できます。

### ポート・保存先を変更する

```powershell
$env:PORT = '8766'
$env:DATA_DIR = 'D:\KeibaData'
.\start.bat
```

ポートを変えた場合は、操作画面とOBSに登録するURLのポート番号も変更してください。同じ保存先で複数サーバーを同時起動しないでください。サーバーは `127.0.0.1` だけで待ち受けます。

## 開発者向け：保存と公開時の保護

- ローカル版は `data/state.json` と直前の `data/state.backup.json` に保存します。破損したファイルは保全し、バックアップから復旧します。
- `design/`、`data/`、`.qa-data/`、添付例のコピー、`.env*`、認証用ファイルはGitの公開対象に含めません。サンプルと公開テストは架空データです。
- Pagesのビルドは明示した23ファイルだけを出力します。保存データや元資料をコピーしません。
- ソースとPages出力を `npm run check:publish` で検査します。APIキー・トークンはアプリに不要です。[保護範囲と注意点](SECURITY.md)も参照してください。

## 開発者向け：開発・テスト・公開

```sh
npm ci
npm test
npm run check
npm run build:pages
git add .gitignore .github package.json package-lock.json README.md TESTING.md SECURITY.md start.bat public src scripts test examples
npm run check:publish
```

開発用パッケージはブラウザ保存のテスト用 `fake-indexeddb` とAPIビルド用 `esbuild` です。公開ページの実行時には使いません。[検証記録](TESTING.md)に確認済みの項目と未検証事項を記載しています。

## 開発者向け：公開JRA API

Pages版では `public/jra-config.js` の公開URLから予定情報・確定結果を取得します。APIキー・ログイン・ローカルサーバーは不要です。予定情報には開催日、結果には開催日・開催場・レース番号だけを送信し、購入記録や収支を送信しません。取得元と取得時刻を画面に表示します。

公開APIはGET/OPTIONSだけを受け付けます。予定は `/api/jra/races?date=YYYY-MM-DD`、結果は `/api/jra/result?date=YYYY-MM-DD&venue=京都&number=11` 、WIN5は `/api/jra/win5?date=YYYY-MM-DD` です。上流はJRA公式の固定URLだけを使い、結果は公式一覧のリンクをたどります（一覧の検索はPOST、個別結果はGET）。任意URLの取得・購入操作は行いません。予定情報は5分、結果一覧・結果は60秒キャッシュします。未公開・開催なし・接続失敗は理由を表示します。CORSはこのGitHub Pagesのオリジンに限定し、実行環境ごとの簡易レート制限も設けています。

APIのソースは `src/jra-worker.js` と共通のJRA取得処理です。SitesのWorkerとして別途配備しています。`npm run build:jra-api` で公開コードだけを `.qa-data/jra-api-site/worker/index.js` にまとめます。配備用認証やSites設定はGitHubへpushしません。APIの変更時はSites側の再配備も必要です。別のWorkerホストに配備する場合は公開URLと許可オリジンを確認してください。

`main` へのpush後、GitHub Actionsがテスト・公開前チェックを実行し、成功した場合だけGitHub Pagesへ配置します。初回はリポジトリの Settings → Pages → Source を **GitHub Actions** に設定します。手動再公開はActionsの「Test and deploy GitHub Pages」から実行できます。

実際のJRAサイトとの疎通を追加確認する場合は `node scripts/check-jra.js YYYY-MM-DD` を実行します。通常のテストはネット接続を必要としません。
